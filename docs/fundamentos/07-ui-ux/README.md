# UI/UX

Objetivo: recuperar el hábito de decidir una interfaz y poder decir por qué. No es un curso de herramienta. Figma entra como el lugar donde se dibuja, después de saber qué hay que dibujar.

UI y UX se estudian juntas aquí porque en un equipo pequeño las hace la misma persona. No son lo mismo: UX es el uso (objetivo, flujo, error, prueba con gente); UI es la forma visible (jerarquía, tipo, color, componentes).

## Al terminar deberías poder

- Nombrar el problema de una pantalla sin decir solo “está fea”.
- Dibujar un flujo con el caso vacío, el error y la carga, no solo el caso feliz.
- Montar un botón, un campo y una tarjeta con estados, y usarlos dos veces sin redibujarlos desde cero.
- Preparar una prueba de cinco minutos con una persona que no seas tú, y anotar lo que hizo, no lo que tú esperabas.

## Criterio de cierre

El proyecto de citas tiene flujo, tres estados de la lista y una nota de qué observaste al enseñárselo a alguien. Si solo hay pantallas bonitas del caso feliz, la asignatura no está cerrada.
